### 部署踩坑全过程
1. **源码分支问题**：本地分支名是 `main`，但 `git push origin source` 要求远程分支名 `source`，本地没有对应分支导致 push 失败。需要在 `_config.yml` 的 deploy 中指定 branch: main（Hexo 静态文件推送目标），源码分支需要单独管理。
2. **.nojekyll 脚本方案失败**：`scripts/nojekyll.js` 在 `generateAfter` 事件中用 `writeFileSync` 写 `.nojekyll`，但 `hexo clean` 后 public/ 不存在，导致 ENOENT 崩溃。**正确方案**：在 `_config.yml` 的 `include` 列表中加 `.nojekyll`，让 Hexo 正常处理 `source/.nojekyll` 文件。
3. **GitHub Pages Jekyll 构建报错**：缺少 `.nojekyll` 文件时，GitHub Pages 会尝试用 Jekyll 构建静态文件，下载 `actions/jekyll-build-pages` action 失败导致部署错误。这跟 Pages 部署模式无关（"Deploy from a branch" 模式也需要 .nojekyll）。
4. **.deploy_git 被污染**：多次部署失败导致 .deploy_git 目录状态混乱，需要 `hexo clean` 彻底清除后重新 deploy。

### 部署正确流程（以后照这个来）
```bash
# 1. 确保 _config.yml 的 include 包含 .nojekyll
# 2. 确保 source/.nojekyll 文件存在
# 3. 执行部署
hexo clean && hexo generate && hexo deploy
# 4. 确认输出中包含 "Generated: .nojekyll" 和 "Deploy done: git"
```

### 关键文件
- `_config.yml` 的 `include: [.nojekyll]` — 确保 .nojekyll 被部署
- `source/.nojekyll` — 空文件，阻止 GitHub Pages 用 Jekyll 构建
- 已删除 `scripts/nojekyll.js` — 脚本方案有 bug，不可用
